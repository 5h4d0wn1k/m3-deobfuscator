# M3 — Deobfuscator

A real, deterministic, **stdlib-only** deobfuscation toolkit for educational
malware analysis. It runs fully offline on any file you hand it and reports
what encoded / obfuscated content it can genuinely recover.

## What genuinely works

Pure-Python passes, all offline and deterministic:

- **XOR lifting** — single-byte (`key=0x00..0xFF`) and repeating-key XOR
  recovery. The repeating-key pass reconstructs the unknown key by the classic
  byte-frequency / "most-frequent-byte-is-space" heuristic, then decrypts and
  scores every candidate by printability + entropy drop. All candidates are
  emitted, ranked by confidence.
- **Base64 / base32 / base16 decode** — scans the file for encoded blobs and
  decodes them back to the underlying bytes, keeping the printable ones.
- **Hex lifting** — decodes runs of hex-encoded bytes (`41424344...` →
  `ABCD`).
- **String extraction** — printable-ASCII string extraction with offset,
  length, and category (URL, IP, registry path, API call, generic).
- **Constant folding (AST)** — a real `ast`-based pass that folds constant
  `BinOp` expressions (`13*100+37` → `1337`, `"api"+"_key"` → `"api_key"`)
  and *flags* (without executing) `eval("...")` sites.
- **Disassembly** — real x86/CPython bytecode disassembly of embedded Python
  via the built-in `dis` module (`LOAD_CONST`/`CALL_FUNCTION` etc.).
- **Suspicious pattern scan + entropy** — nop-sled, anti-debug, persistence,
  network/exfil, `eval`/`exec` signature matching and whole-file SHA-256
  entropy.

Dependencies: **Python 3 stdlib only**. No `python-magic`, no `yara-python`,
no external tools.

## Shipped fixtures (`fixtures/`, generated by `firmware/build_fixtures.py`)

| Fixture | What the tool should recover |
|---------|------------------------------|
| `obfuscated_payload.bin` | single-byte-XOR marker, a 24-byte nop sled, a decoy string, a Base64 beacon, hex bytes |
| `xor_single.bin` | XOR 0x42 of a printable marker |
| `xor_repeat.bin` | 3-byte-key XOR of a printable beacon (spaced text for frequency recovery) |
| `obfuscated_python.py` | benign Python with constant-foldable expressions (`"api"+"_key"`, `13*100+37`), an `eval("'dec'+'oy'")` flag, and Base64-XOR obfuscation |

All fixtures are clearly inert/lab-only.

## Usage

```bash
# Help
python3 firmware/deobfuscator.py --help

# JSON report against a fixture
python3 firmware/deobfuscator.py fixtures/obfuscated_payload.bin -o reports/out.json

# Also emit a Markdown report (out.json.md)
python3 firmware/deobfuscator.py fixtures/obfuscated_python.py --markdown
```

### Offline demos (each exits 0)

```bash
python3 firmware/deobfuscator.py fixtures/obfuscated_payload.bin
python3 firmware/deobfuscator.py fixtures/obfuscated_python.py
python3 firmware/deobfuscator.py fixtures/xor_repeat.bin
```

## Tests

```bash
python3 -m unittest discover -s tests -v
```

11 stdlib `unittest` cases covering XOR single/repeating recovery, Base64 and
hex decoding, constant folding + eval detection, `dis` bytecode, fixture
reports, and CLI exit codes.

## Live Lab Test Plan

1. In an offline lab VM run each `offline demo` above and confirm exit 0 and
   that the report lists the expected recovered payloads.
2. Encode your own control text with a known single-byte and repeating-key XOR
   (e.g. `firmware/build_fixtures.py --help`-style), pass it in, confirm the
   tool recovers it.
3. For a guarded assume-guilty-triple test, XOR plain English with an 3-byte
   key and confirm the correct key length and key bytes are reported.
4. Use only files you own or are authorized to analyze.

## Metrics

- Passes: XOR (single + repeating), Base64/32/16, hex, `ast` constant folding,
  `dis` bytecode disassembly, pattern scan, entropy.
- Test count: 11 stdlib unittest cases.
- Dependencies: Python 3 stdlib only (uses `ast`, `dis`, `marshal`,
  `base64`, `binascii`, `hashlib`, `collections`).
- Offline demo: exits 0 on each shipped fixture and produces real recovered
  payloads in the JSON/Markdown report.

## IMPORTANT: Read before use.

This tool is for **educational and authorized analysis only**. It runs fully
offline and never executes or writes the input — it *reads* files and reports
encoded content. Only analyze files you own or have explicit written
authorization to examine. Recovered strings/IPs may relate to real malicious
infrastructure; do not interact with them outside a controlled lab. The author
is not responsible for misuse.
